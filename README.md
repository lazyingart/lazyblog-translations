# LazyBlog Translations

LazyBlog Translations is the WordPress-side renderer and storage layer for the LazyBlog publishing workflow.

It intentionally stays small:

- stores source language and per-language post translations in post meta
- renders a floating language switcher compatible with the LazyBlog site style
- requests missing translations from the configured LazyBlog local API
- keeps one translation job per post/language to avoid duplicate work
- renders Markdown-origin math with MathJax while avoiding heavy translation-plugin behavior

## Runtime Model

The plugin does not call OpenAI or Codex directly. It calls the LazyBlog API endpoint configured in WordPress admin with a bearer token. The local LazyBlog service owns model selection, prompting, translation, polishing, image handling, and Markdown sync.

This split keeps the public WordPress plugin reusable and keeps private credentials outside WordPress plugin source.

## Security

- Public users can request a missing translation only through a signed, short-lived request generated by the plugin.
- Admin-only REST endpoints require normal WordPress capabilities.
- API calls to LazyBlog use a server-side bearer token stored in WordPress options.
- The source repository must not include `.env` files, API tokens, app passwords, exported post content, or local deployment logs.
